# 헤더 / 푸터 주석 규칙

QA 단계에서 Impl이 만들거나 바꾼 소스 파일에 단다. 테스트 파일, 설정 파일, 자동 생성 파일에는 달지 않는다.

## 헤더 (파일 맨 위)
- 무엇을 하는 파일인지
- 관련 Spec 기능 ID와 Task 번호
- 의존하는 것(외부 API, 환경 변수 이름)

## 푸터 (파일 맨 아래)
- 마지막 QA 날짜와 판정
- 보안 / 유지보수 메모 (알려진 한계, 다음에 손볼 점)

## TypeScript / JavaScript 예시

```ts
/**
 * [파일] 로그인 폼 입력 검증 훅
 * [Spec] F-02 로그인 / [Task] TASK-03
 * [의존] 없음 (환경 변수 사용 안 함)
 */

// ... 코드 ...

/**
 * [QA] 2026-11-02 PASS
 * [보안] 이메일, 비밀번호는 클라이언트 검증만 함. 서버 검증은 TASK-04에서 처리.
 * [유지보수] 검증 규칙이 늘어나면 schema(zod)로 분리할 것.
 */
```

## Python 예시

```python
"""
[파일] 추천 결과 캐시 서비스
[Spec] F-05 추천 / [Task] TASK-07
[의존] REDIS_URL (환경 변수)
"""

# ... 코드 ...

# [QA] 2026-11-02 PASS
# [보안] 캐시 키에 사용자 이메일 대신 내부 ID만 사용.
# [유지보수] TTL 값이 하드코딩됨, 설정으로 옮길 후보.
```

## 갱신 규칙
- 다시 QA를 받으면 푸터의 날짜와 판정만 바꾼다. 이력은 `docs/qa/`에 남는다.
- 헤더에 시크릿 값, 내부 URL, 개인 정보를 적지 않는다. 환경 변수는 **이름만** 적는다.
